## 1. THE UNIVERSAL ATTRIBUTION TUPLE

In an enterprise autonomous agent runtime, accountability requires that any action or artifact can be traced back to its exact originator.

Every proposal, execution, observation, artifact, and ledger record in FORGE carries the **Universal Attribution Tuple**:

$$\mathcal{T}_{\text{attr}} = \left\langle \begin{array}{l}
\text{missionId}, \\
\text{agentId}, \\
\text{incarnationEpoch}, \\
\text{delegationId}, \\
\text{parentDelegationId}, \\
\text{grantId}, \\
\text{planId}, \\
\text{taskId}, \\
\text{capabilityId}, \\
\text{capabilityVersion}, \\
\text{manifestHash}, \\
\text{implementationHash}
\end{array} \right\rangle$$

```typescript
export interface UniversalAttributionTuple {
  readonly missionId: string;
  readonly agentId: string;
  readonly incarnationEpoch: number;
  readonly delegationId: DelegationId;
  readonly parentDelegationId: DelegationId | null;
  readonly grantId: string;
  readonly planId: string;
  readonly taskId: string;
  readonly capabilityId: CapabilityId;
  readonly capabilityVersion: string;
  readonly manifestHash: string;
  readonly implementationHash: string;
}
```

## 2. RECORD-BY-RECORD ATTRIBUTION FIELD MAPPING

The 11 critical ledger record kinds bind specific subsets of the attribution tuple to guarantee immutable auditability:

| Ledger Record Kind | Emitting Entity | Key Attribution Fields Captured | Forensic Purpose |
|---|---|---|---|
| `proposal.created` | Planner (Model) | `missionId`, `agentId`, `incarnationEpoch`, `delegationId`, `planId`, `taskId`, `capability`, `args` | Identifies exact model prompt output and proposed action. |
| `proposal.dispatched` | Authority Gate / Host | `proposalId`, `grantId`, `agentId`, `incarnationEpoch`, `delegationId`, `isolationProfile`, `callerContext` | Identifies which authority grant permitted the proposal and what execution profile was enforced. |
| `observation.created` | Capability Host | `proposalId`, `grantId`, `agentId`, `incarnationEpoch`, `delegationId`, `outputRef`, `evidenceHash`, `consumedBudget` | Binds real physical evidence and resource consumption to the agent identity. |
| `delegation.proposed` | Parent Planner | `parentDelegationId`, `childAgentId`, `requestedAuthority`, `requestedBudget` | Captures original parent intent before attenuation. |
| `delegation.authorized` | Parent Gate | `delegationId`, `parentDelegationId`, `childAgentId`, `effectiveAuthority`, `escrowBudget`, `ancestorPath` | Records the immutable, attenuated authority contract. |
| `delegation.activated` | Host Supervisor | `delegationId`, `childMissionId`, `initialEpoch`, `isolationProfile`, `workspacePath` | Records physical runtime instantiation. |
| `delegation.reincarnated` | Host Supervisor | `delegationId`, `priorEpoch`, `newEpoch`, `reason` | Records monotonic epoch progression and crash recovery. |
| `delegation.revoked` | Host Supervisor / Gate | `delegationId`, `revokedBy`, `revocationReason`, `cascadeDescendants` | Records permanent revocation and affected subtrees. |
| `delegation.receipt_verified` | Parent Gate / Verifier | `delegationId`, `receiptId`, `childLedgerTip`, `verifiedBudget`, `evidenceHashes` | Records parent's cryptographic verification of child work. |
| `delegation.receipt_rejected` | Parent Gate / Verifier | `delegationId`, `receiptId`, `rejectionReason`, `failedStage` | Records failed verification or detected tampering. |
| `delegation.budget_reconciled` | Parent Gate / Escrow | `delegationId`, `totalEscrow`, `auditedConsumed`, `refundedRemainder` | Records final mathematical budget settlement. |

## 3. EVIDENCE ARTIFACT ATTRIBUTION BINDING

When a child agent writes a file or artifact to `workspace/`:
1. **Physical Artifact Header / Metadata:**
   - Artifacts generated by capabilities include a sidecar metadata record:
     ```json
     {
       "artifactSha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
       "byteSize": 1024,
       "attribution": {
         "missionId": "m-01J9...",
         "agentId": "agent-sha256-hash",
         "delegationId": "01J9K...",
         "parentDelegationId": "01J9J...",
         "incarnationEpoch": 1,
         "grantId": "g-01J9...",
         "taskId": "task-04"
       }
     }
     ```
2. **Cryptographic Ledger Reference:**
   - The child's `observation.created` record includes `evidenceHash: "e3b0c4..."`.
   - The parent's `DelegationReceipt` includes the same hash.
   - Any external auditor can correlate the physical file on disk with the observation record, the receipt, and the parent ledger.

## 4. FORENSIC AUDIT QUERY CAPABILITY

With this attribution model, an auditor or security investigator can query the immutable ledger to answer with mathematical certainty:

> **"Which exact delegated agent, under which authority, at which epoch, performed this exact capability execution?"**

* Query: Find all physical actions touching `workspace/production/deploy.sh`:
  1. Ledger index reveals `proposal.dispatched` referencing `deploy.sh`.
  2. Record yields `delegationId: "01J9K4..."`, `agentId: "f4a8b2..."`, `epoch: 2`, `grantId: "g-9921"`.
  3. `delegation.authorized` yields `parentDelegationId: "01J9J0..."` and `ancestorPath: ["root", "01J9J0"]`.
  4. The complete chain of command from root human operator to physical execution is mathematically proven.
