# Evidence-Based Verification in FORGE v1.1

FORGE bans "vibes-based" completion. The model claiming "I fixed the issue and tests pass" is treated as unverified hearsay.

## Verification Tiers

1. **Mechanical Tier**:
   Objective, reproducible facts generated by deterministic test runners or compilers (e.g. exit code 0 from `npm test`, `pytest`, `cargo test`).
2. **Adjudicated Tier**:
   Human or LLM inspection of subjective artifacts (documentation formatting, code cleanliness).
3. **None**:
   No verification performed.

## The Evidence Chain

```
Observation (Command Exit 0) → Supported By Evidence → Verifier Evaluates Criterion → Verdict Recorded
```

Every claim asserted by the model must cite a real, previously recorded `observationId`. If a model asserts a claim without an observation or cites a fabricated observation, the ledger appender immediately rejects it (`claim.rejected`).

## Closure Guard (INV-11)

A mission can NEVER achieve `closure: "verified"` unless:
- Every mechanical criterion evaluates to `result: "pass"`.
- Zero mechanical criteria failed or were inconclusive.
- All cited observations exist in the ledger with verified preimage hashes.
